# Probes

Small standalone programs that check one assumption each about the kernel, glibc, or the Rust
standard library. The research documents in `docs/research/` cite their results. They have no
dependencies; build them outside the repository tree so no binaries land here.

The one-off kits of finished research sessions used to live here too: the tag
`research-logbooks` keeps them.

They need Linux with glibc 2.35 or later, on x86-64 and for the `rseq_` probes on aarch64 too. Results
quoted below are from the reference host (Ryzen 9950X, Linux 7.2.9, glibc 2.43) on 2026-10-16.

| Probe | Build | What it shows |
|---|---|---|
| `rseq_abort.rs` | `rustc --edition 2021 -O rseq_abort.rs -o /tmp/rseq_abort` | An rseq abort can be forced before every instruction of a critical section, unprivileged, with a perf hardware breakpoint that raises SIGTRAP. It aborts a six-instruction push at each boundary and asserts that nothing was committed and the retry succeeds. Works at `perf_event_paranoid=2`. |
| `rseq_readonly.rs` | `rustc --edition 2021 -O rseq_readonly.rs -o /tmp/rseq_readonly` | Writing the top bit of `cpu_id_start` (tcmalloc's cached-slab trick) is not undone by the kernel on `yield` or `spin`, and `migrate` kills the process with SIGSEGV. The kernel no longer rewrites the ID fields on every context switch and enforces them as read-only. |
| `rseq_auxv.rs` | `rustc --edition 2021 -O rseq_auxv.rs -o /tmp/rseq_auxv` | `AT_RSEQ_FEATURE_SIZE=33`, `__rseq_size=33`: glibc registers the full feature size. `__rseq_offset` differs between binaries (it follows the static TLS layout). |
| `cid_stress.rs` | `rustc --edition 2021 -O cid_stress.rs -o /tmp/cid_stress` | Stress test of the two `mm_cid` guarantees: no two threads run with the same cid at once, and an interrupted sequence aborts. Thread counts that flip the kernel between per-task and per-CPU cid ownership, affinity, signal, membarrier, fork and page-fault storms. No violation in any run; the `noarm` control fails as it should. Results in `docs/research/linux-rseq-contract.md`, "Why we do not use `mm_cid`". Run under `taskset`. |
| `rseq_drain.rs` | `rustc --edition 2021 -O rseq_drain.rs -o /tmp/rseq_drain` | Runs the idle-cache drain protocol against live critical sections. With `MEMBARRIER_CMD_PRIVATE_EXPEDITED_RSEQ` no sequence commits after the call returns; with `nobarrier` tens of thousands do. Also prints the cost of a call and shows the command returns EPERM until registered. |
| `cid_exec_fail.rs` | `rustc --edition 2021 -O cid_exec_fail.rs -o /tmp/cid_exec_fail` | A kernel defect: after an `execve` that returns (ENOEXEC, a script with a missing interpreter, or `AT_EXECVE_CHECK`) in a process with more threads than 1.25 times its allowed CPUs, the calling thread's `mm_cid` reads `0x80000000` until its next context switch. Exits non-zero when it sees that. |
| `rseq_lifecycle.rs` | `rustc --edition 2021 -O rseq_lifecycle.rs -o /tmp/rseq_lifecycle` | What `cpu_id` and `mm_cid` hold, and whether the kernel has a registration, in a constructor, `main`, a new thread, thread-exit destructors, a forked child, a `CLONE_VM` child and an `atexit` handler. Registered everywhere except the `CLONE_VM` child, which reads its parent's values. With `GLIBC_TUNABLES=glibc.pthread.rseq=0`: `cpu_id=-2`, `mm_cid=0`, `__rseq_size=0` everywhere. |
| `rseq_preload.rs` | `rustc --edition 2021 -O --crate-type cdylib rseq_preload.rs -o /tmp/librseq_preload.so` | An `LD_PRELOAD` library that checks, on every `malloc`/`calloc`/`realloc`/`free`, whether the calling thread has an rseq registration. No unregistered call in `ls`, `sh`, `perl`, `cargo`, threaded Python with `subprocess`, `os.posix_spawn` and `fork`, or a thread-churning Rust program. |
| `vec_excess.rs` | `rustc +nightly --edition 2021 -O vec_excess.rs -o /tmp/vec_excess` | `Vec<u8, A>` ignores the excess length an `Allocator` returns: capacity stays 10 for a 64-byte block, and `deallocate` receives the requested size. On stable 1.99 the file does not compile (E0658), which shows the trait is still gated there. |
| `clock_ramp.rs` | `rustc --edition 2024 -O clock_ramp.rs -o /tmp/clock_ramp` | The clock a spin gets after the package idled, after a warm-up on some CPU, and after a gap, from each thread's cycles over wall time. Run it pinned off the job's CPUs, under `scripts/measure --both-l3` and `scripts/memlimit`. Results in `docs/research/hardware.md`, "The clock a run starts with belongs to the package". |
| `page_offset_hold.rs` | `rustc --edition 2024 -O page_offset_hold.rs -o /tmp/page_offset_hold` | A load whose bytes overlap, in page offset, a store still in flight is held for it on Zen 5, and when the store's address comes from the load, a loop of them runs one at a time: 2, 10 or 18 to 25 cycles an iteration instead of 1.00, the mode changing in streaks over a run. One byte either side of the store's eight costs nothing. Results in `docs/research/roofline.md`, "A load at the page offset of a store in flight can stall the whole loop" (2026-10-19). Run pinned, under `scripts/measure` and `scripts/memlimit`. |
| `madvise_cost.rs` | `rustc --edition 2024 -O madvise_cost.rs -o /tmp/madvise_cost` | What one `madvise(MADV_DONTNEED)` costs against how many pages it returns, and the laps the process's other threads lose to its TLB shootdowns. Run it pinned, under `scripts/measure` and `scripts/memlimit`. Results in `docs/research/servers.md`, "What returning memory costs a request". |
| `miri-os/` | `cargo +nightly miri run -- <op>` in that directory | A global allocator over `mmap` runs under Miri, including with threads. Miri rejects `madvise`, `partial_munmap`, `mprotect`, `prot_none`, `noreserve` and `asm`. |
| `alloc_profile.rs` | `rustc --edition 2024 -O --crate-type cdylib alloc_profile.rs -o DIR/liballoc_profile.so` | A preload recorder, not a probe of an assumption: wraps glibc's `malloc` family and writes, per process, calls by kind, requested sizes, cross-thread frees and reallocs, realloc growth, peak live bytes and blocks, and lifetimes. Usage in the file's header. |
